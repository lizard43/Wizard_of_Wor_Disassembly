# Wizard of Wor Astrocade Sound Map

This document describes the Astrocade sound hardware and the non-speech sound implementation used by *Wizard of Wor*.

WoW sound effects are generated by the Astrocade custom I/O ICs. The game does not store sampled audio. Its Z80 code interprets compact ROM command streams that update tone, volume, vibrato, and noise registers over time.

SC-01 speech is a separate subsystem.

## Astrocade sound hardware

Each Astrocade custom I/O IC contains an eight-register sound generator. *Wizard of Wor* uses two of these ICs for sound.

| Function | Primary IC | Secondary IC | Description |
| --- | ---: | ---: | --- |
| Master oscillator | `$10` | `$50` | Common oscillator divider |
| Tone A | `$11` | `$51` | Tone A divider |
| Tone B | `$12` | `$52` | Tone B divider |
| Tone C | `$13` | `$53` | Tone C divider |
| Vibrato | `$14` | `$54` | Bits 7-6 speed; bits 5-0 depth |
| Tone C / modulation / noise | `$15` | `$55` | Tone C volume; modulation select; audible-noise enable |
| Tone A/B volume | `$16` | `$56` | B volume in bits 7-4; A volume in bits 3-0 |
| Noise | `$17` | `$57` | Noise modulation mask; upper nibble contributes audible noise level |
| Sound block output | `$18` | `$58` | Eight-register block transfer |

The three tone generators share the master oscillator. Changing the master value changes all three tone channels. Vibrato or noise can also modulate the master oscillator.

The numeric ports overlap the read-side cabinet/input interface. For example, writing `$11` changes Tone A on the primary Astrocade IC, while reading `$11` is part of WoW's player-input path. Sound code should distinguish `IN` and `OUT` use explicitly.

### Volume and noise controls

`$15/$55`:

- bits 3-0: Tone C volume
- bit 4: master modulation source select
- bit 5: audible-noise enable

`$16/$56`:

- bits 3-0: Tone A volume
- bits 7-4: Tone B volume

`$17/$57` is an 8-bit noise modulation mask. When audible noise is enabled through `$15/$55`, its upper nibble also determines the audible noise level.

### Sound block output

The primary block port is `$18`; the secondary block port is `$58`.

For the standard eight-byte transfer, the bytes are written in descending register order:

```text
byte 0 -> $17 / $57
byte 1 -> $16 / $56
byte 2 -> $15 / $55
byte 3 -> $14 / $54
byte 4 -> $13 / $53
byte 5 -> $12 / $52
byte 6 -> $11 / $51
byte 7 -> $10 / $50
```

## Producing a sound directly

The Astrocade IC holds its register values until software changes them. A complete sound effect therefore consists of register writes plus software timing or modulation.

A minimal Tone A test on the primary IC is:

```asm
        ld      a,$80
        out     ($10),a         ; master oscillator
        ld      a,$20
        out     ($11),a         ; Tone A divider
        ld      a,$0F
        out     ($16),a         ; Tone A volume 15, Tone B volume 0

        ; wait or update the sound here

        xor     a
        out     ($16),a         ; Tone A/B off
        out     ($15),a         ; Tone C/noise off
        out     ($17),a         ; noise off
```

The secondary Astrocade IC uses the same register layout at `$50-$57`.

WoW normally does not build effects with isolated direct writes like this. It uses its resident sound engine described below.

## Wizard of Wor sound engine

WoW maintains two software sound-engine records:

| Engine | Record | Astrocade IC outputs |
| --- | ---: | ---: |
| Primary | `$D270` | `$10-$17` |
| Secondary | `$D2AC` | `$50-$57` |

Each record contains the current ROM stream pointer, priority, sound-register image, wait state, and modulation state.

The game requests sounds through four RAM bitfields:

| RAM | Function |
| ---: | --- |
| `$D240` | Request bank 1 |
| `$D241` | Request bank 2 |
| `$D242` | Request bank 3 |
| `$D243` | Request bank 4 |
| `$D244` | Runtime sound/speech service enable |

A request identifier such as `R3.B5` means bit 5 of request byte `$D242`.

The normal path is:

```text
game code sets a request bit
        |
        v
$8003 -> $86C1  Dispatch_Sound_Requests
        |
        v
$851D            Install_Sound_Stream
        |
        v
$8437            Decode_Sound_Stream_Commands
        |
        +--> immediate writes to Astrocade sound registers
        |
        +--> waits and modulators stored in the engine record
        |
        v
$8000 -> $84F2  periodic sound/speech service
        |
        v
$80E6            advance waits/modulators and update the Astrocade IC
```

`$8006` jumps to `$8316`, which resets both WoW sound engines.

### Request priority

WoW uses sound priority levels 0, 1, and 2. `$851D` rejects a new stream when its requested level is lower than the level already active in that engine record.

Request bank 1 has dispatcher precedence. If `$D240` is nonzero, WoW processes that byte and does not process banks 2-4 during the same dispatcher pass.

`R1.B6` resets the secondary engine and `R1.B7` resets the primary engine. These are control bits and are not part of the 24-sound catalog.

`R1.B0` through `R1.B4` reset both engines before installing their sound streams. `R1.B5` is the coin-up request and installs its primary stream without that full reset.

## WoW ROM sound streams

WoW sound streams are interpreted data, not Z80 subroutines. The stream decoder at `$8437` accepts command bytes `$00-$17`.

| Command | Function |
| ---: | --- |
| `$00` | Yield |
| `$01` | Set wait and yield |
| `$02` | Jump to another stream address |
| `$03` | Reset current sound engine |
| `$04-$07` | Load, set, enable, or disable a modulator |
| `$08` | Set engine flag |
| `$09` | Set stream priority to 1 |
| `$0A` | Set stream priority to 0 |
| `$0B-$0F` | Yield aliases |
| `$10-$17` | Write the corresponding Astrocade sound register |

When a stream yields, WoW saves the address of the next command in the engine record. The periodic service advances waits and modulators, then decoding resumes from that saved address.

For example, `R3.B5` installs primary stream `$8A81` and secondary stream `$8A6C`. After each side reaches a wait, the saved next-command pointers become `$8A91` and `$8A7E`. Those are later positions in the same two sound sequences, not additional sound effects.

## Notes

- The native decoders do not use `R2.B5`, `R3.B6`, or `R4.B4-R4.B7` as sound selectors.
- `R3.B2` and `R3.B3` select the same secondary stream at `$8851`.
- `R2.B7` reuses the primary `$8741` stream also used by `R1.B2`.
- `R4.B0` is the only catalog request installed at priority level 2.
- A stream can finish decoding while the Astrocade IC continues sounding from retained register values. Software must explicitly replace or silence those values.
- Stream addresses in the table are entry points. During playback the saved stream pointer moves through waits, jumps, and modulation commands.
